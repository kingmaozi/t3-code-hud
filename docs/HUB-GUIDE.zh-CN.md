# T3 Hub 使用指南

Hub 是 T3 右侧的工作台，可以集中查看任务进度、记忆、技能、MCP 工具、插件、Hooks 和子智能体设置。顶部可切换“记忆库”“技能与 MCP”“插件”“编排路由”“Hooks”“宿主设置”；右侧悬浮仪表盘还提供任务、子代理、Hooks 和插件快捷入口。各 Agent 实际使用什么，仍以对应 Agent 能否读取并应用其配置为准。

## 先从哪里打开

1. 在 T3 进入需要处理的项目和会话。
2. 点击窗口右侧的 **Hub**，或使用 `⌘ ⇧ K`。工作台顶部可切换“记忆库”“技能与 MCP”“编排路由”“宿主设置”。
3. 操作涉及项目时，先确认页面显示的当前项目。切换项目后，项目专用的设置、记忆和计划会随之切换。

右侧还有任务进度入口。它展示的是**当前会话**的计划，不是所有项目的总进度。

## 一、任务进度和产物

右侧悬浮仪表盘默认展开。按住标题栏左侧把手可拖到窗口内其他位置，也可用方向键移动（按住 Shift 可加快）；位置保存在本机。点击“重置悬浮位置”可恢复默认位置；“− / +”用于收起和展开。仪表盘正文过长时在面板内滚动，空间太小时可点“在 Hub 查看完整计划”。底部快捷入口可直接打开“子代理”“Hooks”或“插件”页。

任务面板只显示能确认属于**当前会话**的信息。计划可来自 T3 原生 Plan 或归属已核实的 AGY 会话计划。无法核实会话归属时，不会借用其他项目或会话的计划。

- 有明确步骤（steps）时，显示完成数和进度条。
- 只有 Markdown 计划原文时，显示原文并提示“暂无可计算的步骤进度”，不会从文字猜出百分比。
- 没有主计划时，不会造一个计划或进度条。如果当前会话有真实子任务记录，会单独显示子任务完成、失败、取消、进行中、等待或未知状态；失败计数与计划进度分开。没有计划记录和子任务记录时，会明确显示暂无主计划。

有可计数步骤时，仪表盘标题显示进度环和完成数，例如“2/5 完成”；Markdown 原文和没有主计划的子任务状态不计算成主计划百分比。步骤前的圆圈表示状态，完成项圈内显示勾。Hub 手动计划可以点击圆圈切换完成状态；Agent 原生计划为只读，状态跟随 Agent 更新。在 Hub 的完整计划页中，可以查看步骤，也可以为 Hub 手动计划添加步骤。计划来源和进度以该会话实际可读取的信息为准。

点击产物时：

- **Markdown 文档**：在 Hub 内预览；可关闭预览，或使用“打开所在文件夹”“在 Finder 中显示”定位文件。
- **文件夹或其他文件**：在 Finder 中定位，由你决定下一步操作。
- **文件不存在、超出当前会话范围或归属无法确认**：会提示原因，不能直接打开。

当前产物列表主要来自本机 AGY 的会话产物，项目中的任意文件不会自动出现在这里。产物定位针对本机能核实归属的产物。远端机器上的文件需要通过该远端环境访问，不能假定本机同名路径就是同一个文件。Finder 定位不会替你执行产物中的程序。

## 二、记忆库

打开“记忆库”后，可以按内容搜索已有记录，并按界面提供的范围查看当前项目或全局记忆。涉及具体项目的知识，先确认项目选择正确，再查看或新增记录。

页面上的记忆范围分别表示：

| 范围 | 用来查看什么 |
| --- | --- |
| 智能默认（共享 + 当前工作树） | 当前项目共享记忆与当前工作树的便签；其他可见内容以页面实际结果为准。 |
| 项目长期共享 | 当前项目长期共用的记忆。 |
| 当前工作树便签 | 当前工作副本的便签，不把其他工作树便签混进来。 |
| 全局通用 | 面向不同项目的通用记忆。 |

不同 Agent 能否在当前会话读取这些记忆，取决于它是否接入并调用对应的记忆工具。**看见记忆条目，说明 Hub 能读到；不代表每个已打开的会话都已经读取。**

界面若提供关键词检索与本地向量模型，可按需要选择：关键词检索适合明确的词；向量检索可帮助寻找意思相近的内容。模型状态和索引状态以页面实际显示为准。

记忆库中的“梦境整理 · AutoDream”可分别选择执行 Agent、模型、思考强度和每日时间，保存后读回确认。页面会显示下次计划时间、定时器状态，以及上次本地整理与 Agent 整理各自的结果；没有新增内容或需要判断的候选时会跳过模型调用。T3 和 Hub 需要保持运行，错过时间后可按补跑选项处理；每分钟检查日程不等于每分钟调用模型。

自动整理保留受保护、被引用或无法可靠合并的记录；失败会保留待处理内容并显示原因。新安装默认关闭，已有明确配置保持原值。具体使用与保全规则见 [AutoDream 说明](AUTODREAM.zh-CN.md)。它不代替对话结束时的记忆 Hook，也不表示每轮对话都会自动写入记忆。

## 三、技能与 MCP：先选给谁，再选怎么用

技能是给 Agent 的工作方法；MCP 是 Agent 可以调用的工具服务。两者都在“技能与 MCP”中查看。先选择“Skills 技能”或“MCP 服务”，再搜索对应名称。

需要从 GitHub 添加技能时，可展开“从 GitHub 导入技能”，选择“仅本项目”或“全局”后导入；项目范围需要先打开一个项目。添加自定义 MCP 时，可选择“命令 / URL”或“粘贴 JSON”填写已有的服务配置；新增配置不等于已连接。

### 给某个 Agent 启用

每张资源卡片上的 AGY、Muse、Codex、Pi、Claude 按钮，控制对应 Agent 的配置。点击具体 Agent 后，页面会尝试写入该 Agent 的配置，并重新读取状态。MCP 写入的是该 Agent 的配置，**该 Agent 的其他项目也可能使用这项配置**，不是仅给当前项目临时开启。

如果 MCP 的定义带有环境变量或认证信息，启用时这些配置也可能写入所选 Agent。只需使用其中一两个 Agent 时，逐个选择对应按钮即可。

页面上方的 Agent 按钮用于选择查看谁的启用状态；配合“已启用／未启用”筛选。它本身不是给某项工具启用开关；要操作某个工具，请用该工具卡片里的 Agent 按钮。

“已配置”表示对应配置已写入或读到，不等于工具已经连接，也不保证正在运行的会话已经加载。新会话通常会重新读取配置；已有会话是否即时更新由相应 Agent 决定。“状态未知”“尚未检测”表示信息不足，不应当作已关闭或连接正常。“检测连通性”用于主动检查，结果以当次检测提示为准。

卡片中的来源说明帮助你辨认资源从哪里发现。MCP 标为 Magpie 时，资料来自本机旧 Magpie 库 `~/.config/magpie/library.json`，不等于在线市场的完整、实时清单。其他卡片也可能来自本机已安装的插件或各 Agent 配置。**已登记、Agent 已配置、检测连通、当前会话已加载**是四种不同状态：看见卡片，不代表对应程序一定已经安装或能连接。

Context7 也有两套独立开关：卡片底部的 Agent 按钮控制是否写入所选 Agent 的原生配置；“通过 Hub 使用”选择 Hub 的全局或项目转发方式。关闭其中一处不会自动关闭另一处。若两处都启用，同一服务可能重复出现在工具列表中；按需要保留一种调用路径。

“插件”页和悬浮仪表盘的“插件”入口显示本机发现的**已安装插件**及其技能、MCP、Hooks 等能力概况。该入口用于查看，不会替你从新的在线市场安装插件；插件仍由对应宿主管理。

### MCP 的 Hub 调用方式

每个 MCP 卡片还可以单独选择“通过 Hub 使用”的方式。这与卡片里的 Agent 配置是**两套设置**：前者决定 Hub 如何转发，后者决定相应 Agent 的原生配置。

先选择范围，再选择方式并点“保存 Hub 方式”：

| 选择 | 作用 |
| --- | --- |
| 所有项目默认 | 给没有单独设置的项目使用的默认方式。 |
| 当前项目 | 只为当前项目设置，优先于所有项目默认。 |
| 跟随全局 | 在当前项目范围内撤销单独设置，重新使用所有项目默认；不会修改全局值。 |
| 不经 Hub | Hub 不转发该 MCP；不会自动关闭 Agent 原生配置里的同一个 MCP。 |
| 用到时再连接 | Agent 需要时通过 Hub 查找和调用工具，不必一开始列出该服务的全部工具；适合不常用的服务。 |
| 列出全部工具 | 通过 Hub 将该服务的工具列出来，适合希望直接看到工具清单的情况。 |

例如，一个只在当前工程使用的 MCP，可以把**当前项目**设为“用到时再连接”；其他工程继续使用“所有项目默认”。如果一个 Agent 的原生配置和 Hub 转发都启用了同一服务，工具可能重复出现；按实际需要检查两处设置。

如果某个 MCP 已在“所有项目默认”启用，但当前项目不想经 Hub 使用，可以给当前项目单独选“不经 Hub”并保存。该项目的设置优先；其他项目的默认设置以及 Agent 原生配置不随之关闭。

切换“当前项目／所有项目默认”时，方式下拉会显示该范围实际保存的设置。以后希望项目重新接受全局调整时，选择“当前项目 → 跟随全局”并保存。

“同步五宿主”用于把 Hub 入口同步到可识别的 Agent 配置，可能同时修改多个 Agent 的配置；它不等于把列表里的每个 MCP 都为每个 Agent 启用。同步后仍应检查结果，当前会话的工具列表是否更新取决于 Agent。

保存后能否立刻出现在当前 Agent 的工具清单里，取决于该 Agent 是否支持刷新。找不到刚启用的工具时，先看卡片的配置和连接状态，再尝试新建会话；不要把“保存成功”当作“已经完成连接”。

## 四、编排路由和子智能体

在“编排路由”里，可以查看机器人角色卡、角色层级、执行 Agent、模型和思考强度。角色卡配置的是**这个角色准备使用什么**，不等于每个任务都会自动派给它。Hub 提供 Work（执行）和 Review（审查）两条三级路线：

| 路线 | 默认层级 | 用途 |
| --- | --- | --- |
| Work（执行） | L1 `worker`：Muse / `muse-ember-1.0` / max；L2 `worker-pro`：Sol / `gpt-6.1-sol` / xhigh；L3 主会话兜底 | L1 连续两次未解决时可升 L2；L2 连续两次未解决时由主会话接手。用户明确要求主会话亲自处理时可直接处理。 |
| Review（审查） | L1 `review-fast`：Muse / `muse-ember-1.0` / max；L2 `code-review`：Terra / `gpt-6.1-terra` / max；L3 `review-pro`：Sol / `gpt-6.1-sol` / max | 小改动快审、模块级审查、高风险终审逐级加强。Review L1 和 L3 是新增的建议角色，默认显示为“尚未保存”；展开角色卡并点“保存并注入 AGENTS.md”后才会写入配置。 |

表中是默认建议值。全局角色配置或项目覆盖可能已经更改模型和思考强度；实际任务使用哪个配置，以当前角色卡显示并成功保存的值为准。

这些升级次数由主会话根据同一问题的真实尝试判断；Hub 不会自动计数或启动调度器。角色路由和总指挥策略只有在 **T3 顶层会话**、宿主确实提供 `delegate_task` 等派单工具且规则已加载时才可用。若工具缺失，应报告能力缺口，不能假称已派单。

### T3 分工方式

在全局“编排路由”页的“**T3 分工方式**”中选择一种模式：

- **常规分工**：小、短任务由主会话直接完成；较长任务按需要派单，互不依赖的工作可以并行。
- **总指挥**：主会话以决策、拆解、派单、协调和验收为主，按 Work 层级升级，L1 和 L2 都未解决后再由主会话兜底。

保存会把一份互斥的 T3 协作提示写入已发现的宿主规则托管区块。它是写给 T3 顶层主会话的协作提示，不是自动调度、权限隔离或硬性失败计数；当前宿主可能不执行，已打开的会话也可能需要重新读取规则。子代理不得递归派单。不要再叠加旧 Carbon / Argon 编排块或 AGY 原生蜂群指令，否则可能产生重复或嵌套分工。

旧 Carbon、Argon 和独立蜂群入口已退役；如果 Hub 检测到旧托管提示，可点“关闭旧编排提示”清理旧区块，角色配置不会被删除。当前使用的是上面的“常规分工 / 总指挥”与统一角色卡。

普通角色仍可按职责理解：`explorer` 查资料和定位问题，`worker` 实现并修复，`default` 整理与通用协助，`worker-pro` 处理更难的问题，`frontend` 负责界面，`qa` 负责测试，`code-review` 做独立代码审查。角色卡可调整模型和提示词；某次任务是否实际调用了某个角色，要看任务运行记录。

“全局子智能体”是各项目共用的默认配置；“项目子智能体”用于当前项目明确需要不同配置的情况。优先使用全局默认，确实需要例外时再为项目单独设置。修改模型或思考强度后，要看保存结果；正在运行的子智能体不一定会中途更换配置。

角色卡上的记忆选项表达的是给该角色的协作要求：

| 选项 | 给角色的要求 |
| --- | --- |
| 第一现场读写记忆 | 开工时检索项目记忆；结束时只记录已核实、值得复用的内容。 |
| 只读项目记忆 | 可以检索，不应写入记忆。 |
| 不挂载记忆 | 本子任务不应调用记忆搜索或写入。 |

这些选项需要宿主和子智能体实际遵守对应规则；不要把页面上的选项当成已经验证的独立访问权限隔离。

可从 Hub 顶部“Hooks”页或悬浮仪表盘的“Hooks”入口打开生命周期 Hook 列表。列表只显示全局 Hook 和当前项目 Hook，不会把其他项目的 Hook 混进来。归属某项目的现有 Hook 会明确标出项目范围并显示只读；查看不会改动或同步其配置。全局 Hook 仍可管理，卡片上的“关闭”“仅本项目”“全局”控制其配置范围，关闭 Hook 不会关闭 Agent 或 MCP。外部 Hook 可能只读，内置模板若标为不可用则只是预览；事件能否执行仍取决于宿主支持与规则加载。自定义 Hook 会运行填写的命令，应只使用自己了解的配置。

## 五、项目规则与宿主设置

在“宿主设置”中选择“项目 / 全局 AGENTS 规则”，进入后可以查看规则并返回宿主设置。`AGENTS.md` 用来保存给 Agent 看的协作规则。全局规则是通用默认；当前项目的 `AGENTS.md` 用于项目自己的要求。编辑前先确认正在修改全局还是当前项目，保存后留意页面反馈。

项目规则以项目中的 `AGENTS.md` 正文为准。如果需要让 Claude 查阅该项目规则，可使用“为 Claude 添加项目规则引用”。这个操作添加受管理的引用并保留已有正文；文件存在或引用写入，仍不等于一个已经打开的会话肯定加载了它。

首次打开全局规则时，不会自动把 Codex 的私有规则复制成共享内容。你填写并保存共享内容后，Hub 会更新已发现宿主规则文件中的托管区块，并保留区块之外已有的正文。具体哪些宿主已同步、当前会话是否已经读取，要以界面和宿主实际状态为准。

如果保存时提示文件已被其他操作修改，请重新读取并合并后再保存。角色路由和旧编排对应的托管区块应在各自页面调整，不在规则正文里直接改。项目的记忆软路由只修改项目 `AGENTS.md`；需要 Claude 引用时，再单独点击相应按钮。

“宿主设置”分别展示各 Agent 可读取的配置项。可编辑的字段以页面实际提供的内容为准；配置异常或不支持的项目会只读或显示不可编辑。T3 内运行的 AGY ACP 使用实际 T3 配置实例；页面列出规则文件或显示文件存在，不能据此认定当前 AGY 会话已经加载。AGY 原生设置未接入的部分不能在这里假装修改。

Antigravity 桌面 `.app` 是图形应用，不是 ACP 启动命令。若要在其他编辑器中按官方方式配置 ACP，应使用官方 `agy` CLI，并按官方文档以 `agy acp` 启动服务；不要把 `.app` 路径填成 ACP 可执行文件。参阅 [ACP 接入说明](https://antigravity.google/docs/ide/extensions/acp/)、[CLI 安装说明](https://antigravity.google/docs/cli-install)。Gemini 4 Hydrogen 的模型信息可见[官方模型卡](https://deepmind.google/models/model-cards/gemini-4-hydrogen/)。

T3 自身的设置只开放页面明确支持的项目。例如“下一条提示建议”保存后会重新读取确认；如果连接或该字段不可用，开关不能写入。不同宿主应用新设置的时间可能不同，必要时新建会话再核对。

## 六、速度、缓存和上下文

会话上方的“本轮速度”描述当前这一轮；生成时带 `≈` 的数值是根据可见回复估算的速度。等待首个字时显示“生成中…”，没有可靠的新样本时显示 `--`。悬停统计面板可查看“会话均速”和“末轮速度”。

缓存数字要看范围标注：“本轮缓存”是当前轮内模型调用的综合比例；“最近模型调用（原生记录）”只看最近一次调用；“主会话累计”不含子智能体，“含子代理累计”包括子智能体。它们的数值可能不同；无法可靠读取时显示 `--`。

上下文容量及占用同样以界面标注的数据来源和范围为准，旁边会显示“容量来源”。容量可由宿主自动上报，也可能按本地模型目录或模型家族估算；会随模型、宿主和会话变化，不保证固定为 512K。自动压缩阈值没有可靠上报时会显示未知；模型容量不等于距离自动压缩还有多少空间。

## 七、遇到问题先看什么

| 现象 | 可以先检查 |
| --- | --- |
| 没有看到任务进度 | 确认当前会话；查看右侧任务入口，或在 Hub 打开完整计划。无计划、读取失败和归属无法确认会有不同提示。 |
| 点了产物打不开 | 看它是否还在、是否属于当前会话，以及页面是否提示无法核实归属；非 Markdown 文件会在 Finder 定位。 |
| 点了 Agent，工具仍不可用 | 看卡片是否显示已配置、是否完成连通性检测，以及当前 Agent 是否重读工具列表；必要时使用新会话。 |
| “不经 Hub”后工具仍在 | 这是正常可能性：Agent 原生配置与 Hub 转发是两处独立设置。 |
| 项目设置没有覆盖全局 | 确认选中正确项目，并检查项目是否有单独设置及保存结果。 |
| 记忆库里有内容，Agent 却没用到 | 确认该 Agent 已接入记忆工具，并在当前任务中实际读取了相关记忆。 |
