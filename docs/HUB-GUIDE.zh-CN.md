# T3 Hub 使用指南

当前版本：`1.0.4`（版本以 `package.json` 为准）。本次精简版 Hub 面向电脑端，聚焦两件事：**实时用量显示和项目记忆**。本机真实截图已验证额度环与会话均速显示，Git 入口左移后没有遮挡右侧图标。顶部计划蓝环、记忆入口和开关、向量/MCP 信息面板均已热更新并在本机窗口核验；另一台电脑的完整流程仍未验收。

## 在哪里看信息

| 位置 | 显示内容 |
| --- | --- |
| 聊天标题旁 | 蓝色进度环与“第 N / M 步”显示当前主会话进行到哪一步；悬停、聚焦或点击可查看步骤，不混入子任务。 |
| 顶部栏 | 平台图标居中，外圈周额度、内圈真实 5 小时额度；仅有周额度时只画一圈。Muse 的 300 分钟 Session 窗口也显示内圈。Git 入口位于额度左侧。 |
| 输入框底部、附件与模型选择器之间 | 持续显示会话均速；没有当前速度样本时回退到同一聊天末轮速度，并显示缓存、Token 和费用。 |
| 模型选择器旁 | 当前上下文用量与容量信息。 |
| 标题旁“记忆”和开关 | 点击进入 Memory 工作区，直接切换本机 Agent 记忆访问；不再提供侧边悬浮入口。 |

### 计划与远程项目

计划只按当前 T3 Connect 环境和当前会话读取，使用原生会话投影和受当前项目范围限制的私有镜像。镜像只保留当前主计划，权限为仅用户可读写，并由 Git 忽略；本机已确认镜像的项目与步骤匹配。只有找到可确认的当前主会话计划时才显示入口；无计划或远端读取失败时隐藏入口，不借用其他会话或项目的计划。本机已核验蓝环步骤按钮及展开后的步骤状态。

MacBook 上的 Connect `readFile` 已有真实连接证据；当前选中仓库没有提交记录，因此远程 Git 历史界面、性能和跨机完整流程仍未验证，不能据此宣称 Git 图谱加速已通过。

### 速度、缓存和上下文

会话均速持续显示；当前聊天已有末轮速度时可作为回退值。正在生成且有当前流式样本时，速度随输出刷新；带 `≈` 表示估算值。完全没有测量样本的新会话显示暂无数据，不借用其他聊天的数据。

缓存有真实本轮数据时显示本轮比例；本轮数据缺失但会话累计值真实可用时，会明确标为“累计缓存”。两种数据都不可用时显示“暂无缓存数据”。不会用上一轮、字符数或推测值伪装本轮缓存。Token 和费用按当前会话实际可得的统计展示。

上下文用量旁会标出容量来源。宿主上报、本地模型目录和模型族估算是不同来源；未知时显示未知，不把模型容量当作自动压缩剩余量。

## 使用 Memory

Memory 用来搜索、读取和维护跨会话可复用的项目知识。涉及具体项目时，先确认 Hub 当前项目，再搜索或读取，避免混入其他项目或工作树的记录。

Agent 记忆访问开关直接位于标题旁，关闭与重新开启已通过实际点击核验；Memory 页面提供接入检查及可复制的首次接入提示词。固定 CLI 入口为 `~/.t3/bin/t3-memory-setup`，支持查看状态、接入、启用和关闭。开关关闭后保留所有记忆内容，Agent MCP 访问停止，但人仍可在 Hub 搜索、读取和人工维护记忆。

新启动的 memory-only router 已验证：关闭访问后 `memory_status` 报告 disabled，`memory_search` 被拒绝；重新开启后报告 enabled，并只提供 7 个受控工具。设置总览中 3 个 provider 显示已配置且无冲突。开关按每次工具调用读取，因此新启动的 router 立即遵守开关；本次代码更新前已运行的旧 MCP 进程仍需自然重连才能加载新代码，不必为状态开关本身新开会话。

Memory 的“本机记忆服务”显示正在运行与已配置的向量模型、实际服务端口和状态。MCP 使用本机 stdio，由宿主按需启动，并非 HTTP 服务；复制配置会自动解析本机 HOME，无需手改用户名。关闭开关会拒绝新的 Agent 记忆调用，保留数据库与人工维护，也不强制结束旧会话。

启用后，新增的本机 T3 provider 会被自动检查，并尝试接入受支持的配置。若 Magpie 管理对应原生配置，Hub 不会抢写该配置；无法安全补接时会报告待处理状态。AGY 的 MCP 配置为空或尚未建立时会提示 `agy_native_helper_compatibility`：为避免破坏 AGY 的原生后台文本助手能力，不会静默添加 MCP。已有 MCP 的 AGY 配置可在保留原项目的前提下检查 Hub 接入。

Muse / AGY 的 Hook 状态目前可能显示不支持或未接入；这只描述 Hook 自动提醒能力，不代表 Memory MCP 不能读写。PowerContext 当前与 Hub 使用同一份 Memory 库，不是两套独立数据。向量检索用于查找相关记录，不构成记录数量或长期增长上限。

- 搜索结果保持精简，不把旧版本历史一并塞进搜索上下文。选中记录后可按 ID 读取完整内容和版本历史。
- `pinned` / `core` 记录受保护，不会被自动演进或合并覆盖；需要改动时由人明确编辑。
- 项目、工作树和全局范围彼此区分。按 ID 读取仍受当前项目/工作树范围约束。
- Hub 显示的连接状态只说明找到或读到了相关 MCP、Skill 或 Hook 配置，不证明宿主正在运行、当前会话已经加载或工具实际可用。

Hub 现在只呈现**记忆相关**的宿主配置状态，不负责通用 MCP、Skills、插件、Hooks 或宿主设置管理。要确认运行状态，需看宿主实际加载与调用结果。

## 已退役的 Hub 管理功能

Hub 自建子智能体编排已退役，派单由 T3 原生行为决定。旧路由配置和历史数据保留，不会因为页面移除而删除；不要将配置文件存在当作 T3 已按它派单。

Dream 自动整理已关闭，不再有 Hub 操作入口，也不会由 Hub 自动启动定时器。历史状态和兼容接口保留；普通 Memory 搜索、读取、写入和人工维护仍可使用。

旧版 [AutoDream 说明](AUTODREAM.zh-CN.md) 与 [子智能体说明](SUBAGENTS.zh-CN.md) 仅保留历史背景，不代表当前 Hub 提供这些管理功能。

## 验收边界

远端计划使用当前 Connect 会话的原生投影和受当前项目范围限制的私有镜像；Git 历史首屏采用提交概要优先、选中后再读差异的方案。当前远端仓库没有提交记录，故 Git 历史 UI、性能及跨机完整流程仍未验收。

已完成后端、访问控制、计划镜像和记忆连接模块的局部热更新，安装副本与源码哈希一致，T3 未重启。顶部记忆开关、首次提示词入口、计划蓝环及向量/MCP 信息 UI 已热更新，并完成本机窗口验收。MacBook Connect 的文件读取已验证；由于选中仓库无提交记录，远程 Git UI 与性能仍无有效验收数据。隔离测试、配置状态和局部热更新都不能替代另一台电脑上的完整端到端验证。
