# 可直接交给 T3 的 Hub 自测提示词

复制下面整段到 T3 的新主会话。它是一次以安全可回滚为主的配置链自测：检查开关是否写对作用域、宿主实际看到了什么，不把“文件写好了”当作注入成功。它本身不会自动授权额外模型请求或新子代理派单；如没有明确获准的真实只读子任务，实际派单行为必须标为 BLOCKED。

```text
你现在负责对本机 T3 Hub 做一次只读优先、可回滚的开关注入验收。先阅读当前工程的 AGENTS.md、docs/HANDOFF.md、docs/REQUIREMENTS-AND-EXPERIMENTS.zh-CN.md、docs/HUB-GUIDE.zh-CN.md，以及 docs/SUBAGENTS.zh-CN.md、docs/AUTODREAM.zh-CN.md 中与你要测项目相关的段落。先总结真实工具能力和实时 Hub 路由配置；不要假装使用未挂载的 delegate_task、Hook 或 Agent。

本次目的：逐项确认 Hub UI 的开关是否按预期写入正确范围、由正确宿主读取、并在当前或新会话中产生所声称的行为。分开记录每个证据层：①点击前 UI 值；②当前全局/项目配置备份及归属；③点击后的 UI 值与保存回读；④目标宿主规则/配置的实际内容变化；⑤运行时/当前会话是否读取；⑥行为证据。文件存在或状态显示“已同步”只能证明写入或回读，不等于会话已加载。任何一层不能观察，就标 BLOCKED 并说明缺少的工具/宿主证据。

本提示用于安全配置链自测；若要证明主会话真实派单，必须有用户已授权的只读子任务并实际观察 delegate 工具调用及子代理接收结果。如果本轮没有这个授权，记录“派单行为 BLOCKED：未授权真实子代理工作负载”，不得写成全链路通过。测试 UI/配置开关本身不代表测试了实际派单行为。

硬边界：
- 不重启 T3，不结束或中断用户任务，不安装或升级程序。
- 不触发任何真实模型整理；不要点 AutoDream 的“立即整理”，不要让测试代码调用 memory:dream:run。
- 不登录、不访问认证端点、不发模型请求、不操作/改写/加载 AGY，不增加 AGY 流量。AGY只读查看当前公开的配置路径/文件存在与读回状态；不打开可能产生网络调用的 AGY CLI。
- 不创建付费、外发、权限扩大或安全降级。不要删除或覆盖现存配置、用户规则、项目文件、用户自定义 Agent 或 Hooks。
- 测试中只有可逆且非安全敏感的开关允许实际切换，并且必须一次只切一个、先做权限受限备份和文件哈希、保存后立即回读，再用 compare-and-swap 方式复原原值。若检测到文件在测试期间被用户或其他进程修改，停止复原该文件并报告冲突；不要用旧备份覆盖新编辑。
- 隔离 fixture 优先，先查测试是否真隔离 HOME/T3_HUB_DIR，且不会连到真实 MCP、任务队列或模型。不要把模拟结果写成真实宿主验证。
- 现在全局“总指挥/蜂群模式”为 ON。先读回原值并保护它；结束时必须保留 ON。用户新开的会话仍有主会话亲自写代码且使用旧七角色/code-review high 的现象，这个端到端注入问题尚未证明解决。
- 这不是让你泛化跨宿主。T3 的 AGY 通道、AGY desktop/CLI 各是不同对象；不得因一个宿主结果推断另一宿主。

先只读盘点：
1. 确认当前工作目录、项目根、会话身份、T3 主进程与 Hub sidecar PID，以及 git 分支/未提交修改。动态发现 PID；绝不硬编码 kill 或重启。
2. 找到本工程与 Hub 实际使用的全局配置、当前项目配置、各宿主原生规则文件和 Hook 文件；只记录路径、哈希和待测设置片段，不输出秘密、个人记忆或整份提示词。
3. 导出一个逐字段的最小恢复快照，注明来源路径和生成时间；有文件并发修改时采用 CAS，只复原本次自身写入的字段。
4. 根据 T3 真实可用工具与磁盘路由表，核对目标子代理的 provider、model、reasoning、role 和专属提示词。不要硬套旧对话提供的模型表；配置缺失或工具不存在就报告，不能静默换模型。

按以下项目测试，逐项独立记录 PASS / FAIL / BLOCKED，附安全的文件路径、hash前缀、时间戳、UI回读值或实际宿主证据：

A. 总指挥开关：核对 ON 时总指挥规则与常规规则互斥；守卫不会批准工具、不绕权限、不递归派发。核对 guard 只能改写已经产生的 delegate_task 请求，不会主动派单。最关键的是新会话主提示是否真实读取顶层总指挥规则；若新会话仍自己编码，记 FAIL/BLOCKED，不能用磁盘有规则就判 PASS。不要为了测试在用户任务中制造额外子代理或模型请求。

B. Work/Review 三级：检查 Work L1/L2、Review L1/L2/L3 的实际路由配置、角色、模型、思考级别与项目覆盖优先级；核对用户的自定义规则没有被覆盖，旧七角色/high 现象是否复现。只读测试优先；如果必须保存开关才看到宿主侧效果，先做单项备份与回滚。不要执行真实审查或产生子代理工作负载。

C. MCP 与 Skills：至少选一个安全的隔离 fixture，检查全局/项目作用域开启、关闭、回读、工具名归属和当前 Agent 可见列表。确认关闭某作用域不会删除用户原生 MCP。检查 Context7 是否同时走宿主原生和 Hub 两条路径；发现重复时只报告，不要自行关掉用户现有配置。检查 Magpie 卡片的来源和状态边界；卡片存在、进程探测成功、Agent 已读取工具是不同结论。任何真实 MCP 请求可能访问外网、账号或写数据时，改用 mock fixture。

D. Hooks 与项目规则：核对全局与当前项目范围的 Hook，项目/外部 Hook 若是只读则只检查，不模拟强行改写。核对项目 AGENTS.md 归属准确并可供该项目读取。区分文件存在、托管块一致、当前新会话读取三种状态。不能为了“让显示绿色”重写文件。

E. 计划面板：当前悬浮窗应只呈现本会话主计划/计划文档；子代理清单和进度只在完整任务面板。检查同一项目的正确 thread/native Plan/AGY Brain 计划身份。不应借用其他会话进度，也不应从普通段落造百分比。

F. AutoDream：只读确认 enabled、Muse `muse-ember-1.0`、medium、03:30 Asia/Singapore、catch-up 和 scheduler next due。把“timer started”和“上次 Agent dream status”分开报告。历史真实 Muse 执行返回 `cli-exit-1`、0 条变更；失败根因未知，禁止重试。绝不调用真实模型或手动整理。

结束时执行恢复：逐文件确认只有本测试写过的精确设置仍保持测试值，才恢复原值；核对恢复后的 UI、配置哈希和全局总指挥 ON。把冲突留给用户，不覆盖新编辑。Git 仅只读检查，不 commit/push。最终给我简明结果表，分别写每项证据、缺口、是否更改过以及恢复是否成功；附尚未解决风险。不能把模拟、文件保存、scheduler在线或“推测宿主会读取”写成真实注入成功。不要继续扩展实现，先交自测结果和证据摘要。
```
