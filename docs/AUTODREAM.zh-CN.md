# 自动整理记忆

自动整理会在 Hub 运行期间按设定的时间检查记忆库。新安装默认关闭，已有明确开启的设置保持不变。它先在本机整理完全重复的记录；选择 Agent 模式时，只有发现需要判断的近似记忆，才会把受限数量的摘要交给指定 Agent 判断是否合并。没有达到新增记忆门槛、没有待处理的近似记忆时，可以跳过模型调用。

## 设置时间和 Agent

1. 在 Hub 的记忆设置中找到“自动整理”，开启后选择每天的时间。
2. 选择“仅本地”，或选择“Agent”并设置 Agent、模型和思考强度；完成后保存。
3. 打开运行状态，确认所选 Agent 显示“可用”。这个状态只表示找到了可执行程序，**不代表已登录、模型有权限或调用一定成功**。

时间按运行 Hub 的电脑当前时区计算。要在新加坡时间每天 03:30 运行，应将电脑时区设为 `Asia/Singapore`，再把时间设为 `03:30`；电脑更换时区后，需重新核对。Hub 未运行、电脑休眠或退出时不会在后台凭空运行；开启“错过后补跑”后，Hub 恢复运行会按条件检查并补跑。

目前 Agent 自动整理开放 Muse，可选择其模型与界面显示的思考强度；更高强度可能增加耗时与成本。仅本地模式不调用模型。Codex、Claude、Pi 与 Antigravity 的自动整理适配器尚未完成核验，界面会显示不可用；历史设置仍可查看，但不会启动这些宿主的自动请求。

## 查看结果和处理失败

每次报告分别显示本地整理和 Agent 整理的结果：

- **成功**：对应阶段完成。
- **跳过**：例如没有达到新增记忆门槛、没有需要 Agent 判断的近似记录，或选择了仅本地模式。
- **部分完成 / 失败**：打开报告查看安全错误代码；本地整理成功并不代表 Agent 也成功。
- **待下次处理**：一次处理达到数量或输入预算上限，剩余记录留待之后的计划窗口继续处理。

调用失败时，检查宿主是否可执行、模型名称与权限、登录状态以及网络，然后重新运行或等待下一个计划窗口。界面中的“可用”不会替代这些检查。自动整理会保留受保护的核心、置顶及疑似凭据记录；库内仍被引用的记录，以及历史记录无法完整保留的合并，也会保守保留。报告中的保留数量帮助你了解哪些内容没有被自动处理。近似记录交给 Agent 判断，合并使用既有归档和恢复机制，发生冲突时不会把未完成的合并当成成功。

自动归档使用单独的归档文件，不覆盖旧归档。无法确认工作树已经消失时，旧工作树记忆会保留；目录中还有其他文件时，也不会递归删除目录。

自动整理报告仅使用安全状态和错误代码，不把宿主报错中的原始凭据或完整输出写入报告。模型调用会按配置把有限的待判断摘要发送给 Muse；程序按 Muse CLI 的声明要求空工具预设并禁用写入、Shell 和网页工具，实际账号、模型权限及工具隔离效果仍需以宿主为准。
