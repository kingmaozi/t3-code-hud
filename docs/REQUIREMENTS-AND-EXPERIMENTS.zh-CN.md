# 用户需求与实现试探台账

更新时间：2026-11-16（新加坡时间）。这是需求和证据的交接账，不代表每项已实现。看每项状态时区分**需求**、**代码/配置状态**、**真实宿主是否生效**；“未验证”不得改写成“已完成”。个人会话、记忆正文、认证凭据和原始运行日志留在本机，不复制到公开 GitHub。

## 一、Hub 的资源、记忆和项目共享

**用户目标：** 有全局和项目级插件、Skills、MCP 开关；从 Magpie 本机资源发现可用的 MCP，卡片能显示 Agent 绑定并让用户理解关闭和按需加载；一个项目的多个 Agent 共用项目规则及记忆。记忆保留 shared、worktree、global 等范围，按项目和宿主读取，避免不同项目互相串记忆。

**目前方案/边界：** Hub 把全局资源与当前项目资源分开呈现。Magpie 本机资源库实际发现 6 个 MCP 定义，Magpie 来源卡片不是在线市场的完整清单。卡片状态须区分已登记、已写宿主配置、探测连通、当前会话已加载；“关闭”只表示该处配置不启用，不代表卸载服务或删除资源。“按需加载”要解释资源在 Agent 发起工具使用时才启动；不能暗示点击卡片会把工具强塞进所有运行中 Agent。项目规则来源是该项目自己的 `AGENTS.md`，项目长期记忆共享范围与 worktree/global 范围分开。

**验收方式：** 对单个隔离测试服务分别检查卡片、全局/项目保存回读、宿主配置目标、重新加载后的真实列表及关闭后不调用；检查两个项目的记忆/AGENTS 路由不会串读。Context7 的原生配置与 Hub 转发是两条路径，检查重复可见，不要为消除视觉重复擅自改用户的 native 配置。

**状态：** 已实现部分卡片、作用域和记忆边界；本轮重点是 Hub 分工/注入自测，不应声称 Magpie 在线商店已经完整实现，也不应声称所有宿主的 Hooks/MCP 访问已独立隔离。运行中的会话可能还持有旧工具列表。

## 二、ACP、Python 生命周期与 502

**用户目标：** 修复 ACP 退出崩溃/退出码/信号/管道边界，并明确当前 T3 使用什么通道；不要让额外 Python 行为被误认为反向代理或带来额外账号流量。

**已确认的原始崩溃根因和保护方向：** 旧运行路径使用 Xcode 自带 Python 3.9.6，守护线程收尾时缓冲 I/O 锁与 Python `Py_FinalizeEx` 清理冲突，可触发 SIGABRT；不是证据显示 ACP 子进程本身崩溃。wrapper 已改为偏好 Homebrew Python 并加固信号转发、异常透传、退出码和有限清理；新版 wrapper 已安装。但已启动的 ACP/wrapper 进程不会被替换文件热换解释器或代码，必须等该进程自身自然结束后新进程才采用更新。禁止为验证而中断正在用的 ACP。

**未解决证据：** 历史 `HTTP/1.0 502 Bad Gateway` 的上游原因未被证实，不能说它已经根修。上次核对 T3 使用托管的 AGY ACP 通道，不是另起 AGY CLI；原生 AGY App 与 AGY CLI 是不同对象。用户明确要求不要增加额外 Python 请求或请求重试，避免制造反代/额外流量的表象；只做原有进程的信号、stdout/stderr、退出码转发。不要为了“验证”登录、改变 endpoint、替换 ACP 程序或发真实 AGY 请求。额外请求行为需从源码审计，不从 UI 名称猜测。

**验收方式：** 隔离子进程测 stderr/信号/退出码；真实状态只读核对 wrapper 新旧路径、解释器与进程启动时间。将测试模拟、源码本机安装和真实长驻进程分开报告。

## 三、产物、速度、缓存和上下文

**用户目标：** Artifact 点击可以打开所在文件夹并选中原文件，Markdown 可预览；顶部速度展示本轮，均速放在悬浮信息区；解释缓存命中率口径不一致；上下文容量要随运行时识别，不能写死社区猜测的 512K。

**证据和限制：** 产物 Finder 定位与 Markdown 预览应在真实目标文件/当前项目身份下分别验收。速度要按 streaming、completed、无样本区分；完成轮可用 last decode，而运行时文本增量仅是估算。用户曾提供同一轮缓存约 87.53%、末次调用约 97.27% 两个读数，两者范围不同，不能据此判定一项算错。容量显示应注明来源，区分模型窗口、当前占用、客户端压缩阈值；不把 512K 作为固定阈值。

**状态：** 历史阶段已验过 Finder 与 Markdown 行为，并为速度/缓存口径做过修复；本次新 worktree 中必须按当前文件和实际 T3 读数重查，避免引用旧版本宣称当前安装完成。

最新只读 DOM 核验确认当前 T3 ASAR 里消息容器与消息 ID/role 选择器匹配，未确认“选择器失配”。renderer streaming 分支目前依赖当前消息可见文本增量和采样时长，达到采样条件才显示估算值，未达到则显示“生成中…”；backend 只接受 completed、正 output 且 provider 匹配的本轮 decode 样本，否则不给 lastDecodeTps，也不复用上轮。缓存统计要求同一轮同时有 input 与 cachedInput；运行中缺失是数据未上报，不能硬算。已确认的候选修正仅允许对齐明确归属于当前轮、provider 匹配的样本并标注 `≈`，不得将累计或前轮样本拿来填空。这些都是调查结论，当前没有新实现或真实窗口实测。

## 四、悬浮计划和完整任务面板

**用户目标变更（最新版优先）：** 原先要求计划与子代理进度都放到可拖动悬浮窗，后来明确纠正为：**悬浮窗只保留主会话计划**；子代理列表/进度只放在完整任务面板里。悬浮窗默认展开、自由移动、位置记忆/复位；已完成步骤前用圆圈勾，显示 `N/M 完成`。支持 T3 原生 Plan 和能确认属于本会话的 AGY Brain 计划文件。无主 Plan 时不能把子代理任务百分比冒充主计划进度。

最新交付表达进一步收敛：页面标题统一为**任务面板**；悬浮窗底部子代理、Hooks、插件整排快捷栏全部删除，悬浮只承载主计划。完整任务页在有无主 Plan 时都列真实子代理记录。产物卡片增强易读性，点击用 Finder 直接定位并选中文件，完整任务页仍保留 Markdown 预览。均以同一最新候选的代码、定向测试和视觉证据验收。

**验收：** 切换有 Plan、仅 Markdown/Brain 计划和无主 Plan 的聊天；检查会话/项目身份；检查悬浮窗不显示子任务列表；完整任务页在有无主 Plan 时均列真实子代理；核对拖动/默认展开/收起/重置及步骤勾选。

**状态：** 上一个已提交版本曾真实窗口验证自由拖动和主 Plan/Brain 来源。最新 UI 冻结候选已复制到新交接分支；尚未独立审查或安装到真实 T3。

## 五、三级 Work/Review 与总指挥开关

**用户目标：** 机器人头像；Work/Review 两条三级链路，可设置 Agent、模型、思考强度、系统提示词。总指挥开关关时小任务主会话处理、长任务再派；开时主会话作决策拆分和派单，子代理执行，Work L1 两次不成升 L2，L2 两次不成才主会话接管。避免与 Swarm/AGY 原生编排叠加和递归子代理。

**关键核验发现：** 当前全局模式为**总指挥开启**，不要恢复 OFF。六宿主托管规则块可读回显示 ON 与九角色，但用户新开的聊天仍会自行编码、呈现旧七角色并将旧 `code-review` 显示为 high。故此端到端目标尚未验收。route guard 只有在 `delegate_task` 已触发时才改目标，不负责让主会话主动派单。仅看文件写入或卡片选中不能证明新对话执行了总指挥规则。

实际 AGY 安装副本的 GEMINI_HOME profile/config、skills 中 `t3-subagent-routing/SKILL.md` 和 `~/.agents` 副本还有旧七角色/high 内容，与 Hub 新规则及 AGY UI 的默认协作提示冲突。AGY ACP 内嵌 external pre-invocation hook 明确提示 `injectSteps` 不受 SDK 支持并被 Ignored；不能将网页中的普通 AGY hook 文档外推为该 ACP hook 可用。Codex `UserPromptSubmit`/`additionalContext` 目前只是一条提案；native session/turn 标识时序、顶层识别和实际注入尚未完成验证或安装，也不能跨宿主泛化。

ASAR 调查还发现 T3 运行时的 AGY user-skill 与 orchestration prompt 可能仍包含“普通编码由主会话处理”的旧提示；ACP prompt 在新建/加载/恢复时注入，与开关保存后对现有会话热更新不是一回事。源码偏移只对应当时特定 ASAR 快照，禁止硬编码补丁。官方 AGY web Hooks 文档列有 `injectSteps`，但本机 ACP 包明确显示该 SDK 字段被 ignored；不能把两个接口混为一谈。Codex `UserPromptSubmit`/`additionalContext` 是另一个可研究候选，native thread/turn refs、父子 lineage 与时序都需先验证，不能跨宿主照搬。

**安全验收：** 先快照用户/项目/各 native 宿主配置；在测试副本验证规则合成、CAS/回滚、项目覆盖与角色路由。若获准测试真实开关，每次仅改一个可恢复设置，并核验 UI→保存回读→宿主文件→runtime/fresh chat。保存后必须复原原始模式 ON 和原提示词，同时保留手动编辑冲突。不可覆盖 AGY 私人/用户管理的配置，尤其不得发 AGY 模型请求来“看有没有触发”。

## 六、AutoDream 梦境整理

**已保存配置：** Muse (`muse-ember-1.0`)，`medium`，每天 `03:30`，`Asia/Singapore`，启用且开启休眠唤醒补做。页面显示定时器运行只是 scheduler 状态，不证明 Agent 调用成功。

**真实验证结果：** 用户明确授权的第一次手动执行本地整理成功，Agent 返回 `cli-exit-1`，0 条记忆变更。后来仅针对临时 prompt-file 输入故障修复并离线检查后，主会话进行了第二次实际验证，仍返回 `cli-exit-1`，0 条变更。Muse CLI 为 1.4.20；生产参数帮助显示名称有效。隔离离线参数探针成功通过参数校验并进入模型 streaming，但由于测试网络明确 deny 而失败，不能作为真实请求根因证据。真实调用的 stderr 原因未保存在持久报告，根因仍未知；不能推断为认证、模型、网络或预算问题，estimated tokens 为 0 也不能保证未计费。不要再次调用真实模型、改认证、查账号登录、操作 AGY。

临时 prompt-file 安全修正已装：0700 临时目录 + 0600 普通文件，在 finally 中按 inode 校验后非递归清理；独立52/52、增量54/54、promptfile专测8/8。新加 `tests/hub-autodream-diagnostic.test.cjs` 是保留的目标红测，当前18/18失败，源码尚未实现 `report.agent.diagnostic` 安全摘要。下一实现应只从内存里的 stderr 提取白名单错误类别/HTTP状态，不写原始 stderr、prompt 或记忆正文；文档与验收不可将该红测说成全套绿。

**下一步安全方向：** 只从目前内存中可获得的、经正则白名单过滤的退出状态提取安全错误类别并写入报告，绝不写 raw stderr；用伪造 child stderr 的单元测试验收。然后在离线 fake runner 验证完整簇筛选、merge建议校验、冲突保留/归档恢复和真实报告状态。新的真实模型验证必须由用户明确授权，并在结果不确定时禁止自动重发。

详见 [实现试探、被否定的判断与接续注意事项](EXPERIMENTS-TIMELINE.zh-CN.md)，其中保留 ASAR 误判撤回、Python 多轮边界返修、模式注入无效路线及梦境两次失败等经过。

## 交接执行顺序

1. T3 先读 `AGENTS.md` 与 `docs/HANDOFF.md`，查看当前模式配置和所有未提交文件。
2. 先验证总指挥提示是否能在**新会话开头真正加载并改变主会话行为**，再讨论 Codex-only Hook 或 AGY-only workaround。
3. 合入正在修正的悬浮窗布局并在隔离 fixture 验证，再由用户授权时做实际热加载检查；无需仅为文档而重启 T3。
4. 不得将 AutoDream “定时器运行”报告成“Agent 可用/成功”，先补齐安全错误证据和离线边界测试。
5. 每个结果分开写：代码、安装、当前宿主加载、真实 UI 行为和真实模型执行。
