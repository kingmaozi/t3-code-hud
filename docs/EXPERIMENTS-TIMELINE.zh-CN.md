# 实现试探与接续注意事项

更新时间：2026-11-18。当前产品范围以 [需求与实现状态](REQUIREMENTS-AND-EXPERIMENTS.zh-CN.md) 和 [T3 Hub 使用指南](HUB-GUIDE.zh-CN.md) 为准；版本从 `package.json` 读取（当前 `1.0.6`）。下列旧尝试只保留会影响安全判断或接续工作的结论。后端与接入模块已局部热更新；本机顶部界面已完成热更新与验收；远端 Git 历史的完整流程仍待验证。本机日志、记忆和截图留在忽略目录，不提交。

## 2026-11-18：自动项目绑定接线

- 仅凭目录标记不足以确定 T3 选中的项目。新增只读登记查询，优先核对可信启动会话身份，否则要求目录与项目或映射后的工作树精确且唯一匹配；不遍历聊天全文。
- 同仓已登记 A、B 子项目时，即使只有 A 的历史 thread 提到某个 checkout，也不能据此把整个 checkout 根绑定到 A。需要枚举同仓登记项目核对；具体子项目目录和可信会话身份可以消除歧义。稀疏工作树缺失其他登记子目录时仍保守拒绝不明确的根目录绑定。
- MCP 首次确认项目后固定归属，后续每次调用核对路径。技能自动取得并传递路径，避免旧示例省略必需参数；失败的解析可重试。共享 provider 进程缺少可信会话身份时仍可能不可用，不能以自动注册代替逐宿主行为验证。
- 向量服务状态会自动显示；实际计算探针仍由按钮触发。保留的历史成功结果不是刚发生的新测试。本轮不重做该 UI。

## 2026-11-18：项目记忆隔离与实际向量测试

- 旧默认全局回退、仅凭记录 ID 修改、同仓子项目折叠、兄弟工作树文件同步和工作树名称清洗碰撞都会破坏归属。当前读写、回滚、同步、统计和向量重建统一按项目及当前工作树限制；未知项目不选最近会话。旧全局和无法确认归属的旧私有记录原地保留，不自动迁移。
- 两个同名项目同时首次访问时，锁外挑选目录名会产生争用。新版在进程间锁内完成身份占用；已有身份的普通搜索不持该全局锁执行向量计算。确定性交错回归覆盖 14 个入口。若旧进程已产生混合归属记录，新版暂停相关操作并保留数据，不返回另一项目的内容。
- T3 的 thread.worktreePath 是整个 checkout 根；项目可以是仓库内子目录，因此必须结合注册项目相对路径解析记忆目录。第三方 MCP 没有统一可信 thread ID，不得把 cwd、配置状态或当前窗口显示单独当成所有 Agent 已完成绑定的证据。
- 本机独立 MLX 服务由 LaunchAgent 管理，不依赖打开 oMLX。实际按钮测试验证了有效非零向量、模型与维度。测试发送固定无隐私短句，不读写记忆、不启动或切换模型。服务健康、真实计算成功、配置已保存是分别报告的状态。

## 当前远端计划与 Git 首屏状态

- 远端计划读取同一 Connect 会话的原生计划投影，并可使用当前项目范围内的私有主计划镜像补足。镜像权限为仅用户可读写并由 Git 忽略；本机确认项目和步骤匹配。蓝环计划按钮及步骤展开已在本机核验。
- Git 首屏采用提交概要优先，选中后再读差异详情。MacBook Connect 的 `readFile` 已有真实连接证据，但当前选中仓库没有提交记录，因此远程 Git 历史 UI、性能及完整跨机流程尚未验证。

## 2026-11-17：遥测、Memory 接入与计划镜像验收

- 本机真实截图已验证会话均速和平台图标周边的 5 小时额度环，周额度在外圈，真实 5 小时额度在内圈；Git 入口左移后没有遮挡右侧图标。不在公共文档记录具体速度值。蓝环计划按钮已完成本机核验。
- Memory access/backend、计划镜像和连接状态模块已局部热更新且副本哈希一致，未重启 T3。新启动的 memory-only router 初始化成功；关访问后状态为 disabled 并拒绝搜索工具，开访问后状态为 enabled 且提供 7 个受控工具。3 个已启用 provider 的配置状态为 configured、无冲突。
- 固定 CLI 为 `~/.t3/bin/t3-memory-setup`。开关每次工具调用都会读取；关闭保留所有记忆内容和 Hub 人工维护能力。只有本次代码更新前已经运行的旧 MCP 进程需要自然重连以加载新代码，不需为开关状态新开会话。新增本机 T3 provider 在启用后会被自动检查。
- 自动接入尊重现有配置管理器。Magpie 管理的原生配置不由 Hub 覆写；AGY 空 MCP 配置标记 `agy_native_helper_compatibility` 并保持待处理，避免影响原生后台文本助手。已有 MCP 的 AGY 配置可在保留其他条目的前提下接入。
- Hook 支持状态与 MCP 读写能力分别判断：Muse / AGY Hook 暂不支持或未接入，不意味着对应 provider 的 Memory MCP 不能读写。PowerContext 当前共用 Hub Memory 库；向量检索不会限制库内记录增长。
- 顶部记忆开关已实际点击验证，首次提示词入口、蓝环计划及向量/MCP 信息均已热更新并核验。MacBook Connect 文件读取已连通，但选中仓库没有提交记录，不能据此声称远程历史 UI、性能或跨机完整流程通过。

- Muse 第二圈缺失的根因是窗口转换丢弃 `windowDurationMins`。现在保留该字段，仅明确为 300 分钟或有明确 5 小时证据时绘制内圈；新增回归及本机双环显示验证通过。

## 已核实且仍适用的产品约束

- **当前会话身份：** 曾出现 URL hash 仍指向 `/draft/...`、而 T3 内存路由已进入真实会话的情况。若只看 hash 会把会话误判为草稿、沿用错误上下文。早先 renderer 修复按已解析路由优先并在首页清空旧会话；当时已做本机真实窗口核验。新 `1.0.4` 候选的整体验收仍需单独确认。
- **速度与缓存：** 活跃速度依据当前输出实时采样并标注估算；缓存若无本轮真实 token，就不能用字符数、旧轮或其他会话值填充。当前界面本轮数据缺失时可显示有明确标签的会话累计值；没有真实累计值则显示无数据。
- **Memory 搜索与保护：** 搜索结果省去旧版本历史以降低输入负担；显式按 ID 读取可取回完整历史，但仍应用项目/工作树过滤。`pinned` / `core` 记录不参与自动演进或合并覆盖；人工明确编辑与自动整理需分开处理。
- **运行状态判断：** 配置存在、RPC 可连、进程在运行、当前会话已加载是不同证据。任何一项都不能单独代替实际宿主行为验收。

## 已被新决定取代的历史路线

- Hub 自建总指挥、角色路由和对宿主写入编排提示已不再是产品目标。曾经“配置为 ON、角色卡存在”并没有证明 T3 新会话会派单；route guard 只处理已经发生的 `delegate_task`，不会让主会话主动派单。现在派单以 T3 原生行为为准，旧配置和用户数据保留，不因退役而清理。
- Dream 自动整理已关闭。历史上两次经授权的模型运行都以 `cli-exit-1` 结束、未产生记忆变更；安全错误根因未保留下来，不能据此推断认证、模型、网络或费用状态，也不再发起真实重试。
- 旧的 `ensureDreamScheduler` 入口因 bridge 热重载兼容性保留，但现在只停止旧定时器并返回状态，不会重新启动 scheduler。手动 Memory 功能继续可用；隔离测试使用假 timer，不执行真实 Dream。
- 旧 Hub 的 MCP/插件/Skills/Hooks/宿主设置管理和 Dream、子代理编排指南仅供历史参考，不作为当前界面承诺。

## ACP 与敏感操作的旧经验

旧 ACP wrapper 曾修正 Python 收尾、信号与退出码转发；已经运行的进程不会因为文件更新就自动加载新代码。历史 HTTP 502 的上游根因仍未知。不要把已安装 wrapper 说成 502 已根治，也不要为了诊断改 AGY 认证/endpoint、重放请求或发额外模型调用。stderr 和记忆正文可能含敏感内容，不能写入公开日志或仓库。
